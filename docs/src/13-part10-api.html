Part TenREST API Specification

10.1 Conventions

RuleSpecification
Base path/api/v1. Versioned from day one — the reference platform's unversioned /api leaves no way to change a response shape without breaking every cached client.
Content typeapplication/json; charset=utf-8, except upload endpoints which accept multipart/form-data.
CasingcamelCase in JSON; snake_case in the database. The mapping happens once, in the serialisation layer.
IdentifiersPublic identifiers only — slugs, order numbers, ULIDs. Numeric primary keys are never returned.
MoneyReturned as an object: {"amount": 35000, "currency": "TZS", "formatted": "TZS 35,000"}. The server formats, so a price never renders differently in two places.
TimestampsISO 8601 with an explicit offset: 2026-08-19T14:32:05.123Z. Always UTC.
Status codes200 read or update · 201 create, with a Location header · 204 delete · 400 malformed · 401 unauthenticated · 403 unauthorised · 404 absent · 409 conflict · 410 gone · 422 validation · 429 rate limited · 500 server.
Success assertionClients must test response.ok — the 2xx class — never a specific code. Fixes defect R8.
CollectionsAlways an envelope, never a bare array:
{"data":[…],"meta":{"page":1,"pageSize":24,"total":617,"pageCount":26},"links":{"next":"…","prev":null}}. The reference platform returns bare arrays, which means a paginated response can never be introduced without a breaking change.
Single resources{"data":{…}}. Same reason.
Sparse fields?fields=id,name,price on read endpoints for expensive lists.
Expansion?include=variants,images,reviews. Each endpoint documents which expansions it accepts; unknown values are a 422, never silently ignored.
Sorting?sort=-createdAt,name. A leading minus is descending. Only whitelisted fields.
Pagination?page= and ?pageSize=, default 24, maximum 100. Cursor pagination (?cursor=) additionally on audit_logs, order_events and search_logs, where offsets get expensive.
IdempotencyIdempotency-Key header honoured on POST /orders and POST /payments. Replays within 24 hours return the original response.
CorrelationEvery response carries X-Request-Id, echoed into logs and shown on error screens.
DeprecationRetiring an endpoint sends Deprecation and Sunset headers for at least 90 days before removal.

10.2 Error format

One shape for every error, at every status code.

{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Some fields need attention.",
    "requestId": "01JBQ7X2K9P3M4N5Q6R7S8T9V0",
    "details": [
      { "field": "phone",    "code": "invalid_length",
        "message": "Phone number must be 12 characters long" },
      { "field": "items[2].quantity", "code": "insufficient_stock",
        "message": "Only 2 available", "meta": { "available": 2 } }
    ]
  }
}
CodeStatusRaised when
VALIDATION_FAILED422Zod parse failed. details lists every failing field, not just the first.
UNAUTHENTICATED401Missing, malformed or expired access token.
FORBIDDEN403Authenticated but lacking the required permission.
NOT_FOUND404No such resource, or one the caller may not see. Never distinguishes the two.
GONE410Soft-deleted resource that used to be public.
CONFLICT409Unique constraint or a state-machine violation.
PRICE_CHANGED409Checkout revalidation found a different price. details carries old and new per line.
INSUFFICIENT_STOCK409Checkout revalidation found too little stock. details carries the available quantity per line.
INVALID_STATE_TRANSITION409Order status change not permitted by §12.7.
TOKEN_INVALID400Verification, reset, payment or invoice token bad, used or expired — one code for all four cases, deliberately.
RATE_LIMITED429With a Retry-After header.
PAYLOAD_TOO_LARGE413Body or upload over the cap.
UNSUPPORTED_MEDIA_TYPE415Upload MIME type not on the allowlist.
INTERNAL_ERROR500Message is always generic. Details go to logs, never to the client.

10.3 Authentication endpoints

VerbPathAccessBehaviour
POST/auth/registerpublicBody {username, email?, phone?, password, acceptedTerms}. At least one of email or phone required. Creates the user, issues tokens, queues a verification email. 201.
POST/auth/loginpublicBody {identifier, password} where identifier is an email or a phone. Sets the refresh cookie, returns the access token and profile. Rate limited per §10.9.
POST/auth/refreshcookieRotates the refresh token, returns a new access token. Reuse of a rotated token revokes the whole family (§11.2).
POST/auth/logouttokenRevokes the current session and clears the cookie. 204.
POST/auth/logout-alltokenRevokes every session for the user.
GET/auth/oauth/:providerpublic302 to the provider with PKCE and a state parameter.
GET/auth/oauth/:provider/callbackpublicValidates state, exchanges the code, links or creates the user, then 302 to the SPA with a one-time exchange code — never with a token in the URL, which would leak through referrers and history.
POST/auth/oauth/exchangepublicSwaps the one-time code for a session.
POST/auth/email/verify/requesttokenRe-sends verification. Limited to 3 per hour.
POST/auth/email/verifypublicBody {token}. Marks verified.
POST/auth/password/forgotpublicAlways 200 with the same body, whether or not the address exists.
POST/auth/password/resetpublicBody {token, password}. Revokes all sessions.
PATCH/auth/passwordtokenBody {currentPassword, newPassword}. Revokes other sessions.
GET/metokenCurrent profile, roles and permission keys.
PATCH/metokenBody {username?, email?, phone?, marketingOptIn?}. Changing email clears verification and re-sends.

10.6 Payments

VerbPathAccessBehaviour
GET/pay/:tokentokenOrder summary for the delegated payer. Deliberately omits the buyer's address, phone and email.
POST/pay/:tokentokenBody {paymentMethod, paymentNumber}. Records a payment as pending. Single-use: the token is consumed.
POST/orders/:orderNumber/paymentsownerRecords a payment attempt against the caller's own order — the "Pay now" path from order detail.
POST/webhooks/payments/:providersignatureAggregator callback. Verifies the signature, writes a payment_events row, then processes idempotently by external_event_id. Always returns 200 once persisted, even if processing is deferred — a provider that receives a non-200 will retry forever.
POST/admin/orders/:orderNumber/payments/:id/verifyadminMarks a manual payment settled. Body {providerReference, amount, note?}. Transitions the order and fires notifications.
POST/admin/orders/:orderNumber/refundsadminBody {amount, reason}. Records a refund and restores stock when the order was already fulfilled.
