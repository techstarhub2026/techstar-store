Part FourteenAdmin Console Specification

The brief asks for "full CRUD ability to manipulate anything in the platform". This part delivers that literally: every entity in the data model has a create, read, update and delete path in the console, plus the bulk operations, filters and safeguards that make those paths usable at scale. §14.19 states the universal contract that every module below conforms to, so the individual sections describe only what differs.

14.2 Dashboard

Purpose. Answer "what needs my attention right now" and "how are we doing" in one screen, without scrolling past the fold for the first of those.

14.2.1 Attention strip

The top row, and the reason the page is opened. Each tile is a filtered link; a tile with a zero count renders muted rather than disappearing, so its absence is never mistaken for a missing feature.

TileContents and threshold colouring
Awaiting payment verificationCount of orders with payment status pending_verification. Amber past 2 hours, red past 24. Links to the filtered order queue.
Orders to fulfilCONFIRMED and PROCESSING counts.
Low stockVariants at or below their threshold. Links to the stock report sorted ascending.
Pending moderationComments plus reviews awaiting a decision.
Failed webhooksUnprocessed payment_events. Red whenever above zero — this tile should always read zero.

14.2.2 Metric tiles

Four StatCards, each with a period selector shared across the row (Today · Last 7 Days · Last 30 Days · Last 12 Months) and each showing the value, the change against the immediately preceding period of equal length, and a sparkline.

  • Sales — sum of total_amount for orders paid in the period.
  • Orders — count of orders placed in the period.
  • Average order value — sales ÷ orders.
  • Customers — new registrations in the period, clickable to a breakdown modal by region.

14.3.2 Product create and edit — the variant matrix

This is the most important screen in the console: catalogue growth is bounded by how fast a product can be entered, and the target is under three minutes (§3.6). The reference platform's attribute-matrix design is good and is kept, with its rough edges removed.

SectionFields and behaviour
1. ClassificationSubcategory — a searchable select grouped by category, required. Choosing it derives and displays the SKU prefix immediately, so the administrator sees the code the product will receive before saving.
2. DetailsProduct name (required, 3–255, trimmed and whitespace-collapsed on blur, with a live duplicate-name warning that informs but does not block) · Short description (plain text, 500, used for meta description with a live SEO preview) · Description (rich text, required) · Brand · Manufacturer part number · Tags (create-as-you-type).
3. PhotosDrag-and-drop uploader, up to 100 files, 3 MB each, JPEG/PNG/WebP/AVIF. Reorderable by drag; the first is the display image unless another is starred. Each accepts alt text. Upload begins on drop with per-file progress. Derivatives are generated asynchronously and the UI shows a "processing" state rather than a broken thumbnail.
4. Pricing & stock — simpleWhen no attributes are defined: Price (required, > 0) · Compare-at price (optional, must exceed price) · Cost (optional, staff-only) · Available stock (required, ≥ 0) · Low-stock threshold (default 5) · Barcode. One variant is created behind the scenes.
5. Pricing & stock — variantsIntroduced by "Add attributes", with the explanatory line the reference platform uses: "Add specifications to your product here. Skip this step if the product does not have any special specifications." The matrix then appears as a table whose columns are the attributes plus fixed Price and Stock. "+" adds an attribute column, prompting for its name and optional unit. "Add new values" adds a row. Each cell validates on blur. A row may be removed; "Delete table" clears the matrix back to the simple form after confirmation. Every row becomes one variant with an automatically assigned SKU shown read-only in a leading column.
6. VisibilityStatus — Draft / Active / Archived, default Draft, so a half-entered product is never live. Publish date (optional, schedules activation). Featured flag.
7. SEOURL slug — auto-generated, editable at creation. On edit it is read-only with a "Change URL" control that warns about link breakage and offers the 301 redirect described in §6.6. Meta title (70) and meta description (160) with counters and a search-result preview.
FooterSticky. "Cancel" · "Save as draft" · "Save and add another" · "Save" primary. Disabled until dirty and valid. Leaving with unsaved changes prompts.

Improvements over the reference implementation A draft status, so nothing goes live half-finished. A visible SKU before saving. A duplicate-name warning. Editable alt text. Variant SKUs shown in the matrix. A "Save and add another" path for bulk entry sessions. And the matrix keeps its state when validation fails — the reference platform's implementation loses unsaved rows on a failed submit, which is the single most expensive small defect in the whole console.

14.3.3 Stock management

A dedicated screen at /admin/stock, listing variants rather than products: thumbnail, product name, attribute values, SKU, on hand, reserved, available, threshold, last movement. Filterable to low or out of stock; sortable by available ascending, which is its default. Inline "Adjust" opens a dialog taking a signed delta or an absolute count, a reason from the fixed list (purchase, adjustment, damage, return, stocktake), and a note required for deltas above 10. Each variant has a "Movements" drawer showing its full ledger. Bulk adjustment by CSV upload — SKU, delta, reason — is provided for stocktakes, with a dry-run preview before commit.

14.3.4 Discounts

Reachable from a product row action and from a dedicated list. The modal takes Discount (%) or a fixed amount, Discount start date and Discount end date — the reference platform's three fields — plus scope (this variant / this product / this subcategory / this category) and an active toggle. A live preview shows the resulting price for the affected items and warns if the discount would take any price below one shilling. The list view shows all discounts with scope, value, window, affected item count and status, filterable to active, scheduled or expired.

AspectSpecification
Category listColumns: selection · Name · SKU code · Subcategories (count) · Products (count) · Position (drag handle) · Status · Created · Actions. Rows are drag-reorderable, which writes position and immediately changes the storefront mega-menu order.

Subcategory listColumns: selection · Name · Category · SKU code · Products (count) · Position · Status · Actions. Filterable by category.
Subcategory create / editCategory (searchable select, required) · Sub-category name · SKU (4 digits), auto-suggested as the parent's code plus the next free sequence, with the parent's two digits shown fixed and only the last two editable — which makes an invalid code impossible to type.
DeleteRefused while children exist, per §9.5. The dialog states the blocking count and offers the two supported paths: "Move products to another subcategory" or "Delete the products first". This is the fix for defect R12 — the reference platform instead offers to cascade-delete every product in the tree.
Move productsA dedicated action: choose a destination subcategory, review the count, confirm. SKUs are preserved (§12.1) and the move is audited.

14.5.1 Order queue

AspectSpecification
Status tabsAll · Awaiting payment · Awaiting verification · Confirmed · Processing · Shipped · Delivered · Completed · Cancelled · Expired — each with a live count. The reference platform offers only All / Completed / Pending / Cancelled, which cannot express the working day.
ColumnsOrder number (monospace) · Date · Customer name · Phone · Items (count) · Total · Payment status pill · Fulfilment status pill · Shipping method · Region · Actions.
SearchOrder number, customer name, phone, email, payment number, or a product SKU within the order.
FiltersDate range, payment method, shipping method, region, amount range, has-delegated-payer.
Default sortPlaced date descending — except on the "Awaiting verification" tab, where it is ascending, oldest first, because that is a work queue and the oldest item is the most urgent.
Bulk actionsUpdate fulfilment status · Print packing slips · Export CSV. Deliberately no bulk cancel and no bulk delete — an order is a financial record.
RealtimeA new order inserts at the top with a brief highlight and an audible chime, subject to a per-user mute. This is what the reference platform's Socket.IO connection exists for.

14.5.2 Order detail

Two columns. Left (8 of 12): status bar, items, payment panel, fulfilment panel, timeline. Right (4 of 12): customer card, shipping card, totals card, internal notes.

PanelSpecification
Status barOrder number, placed date, and the three status pills. A "Change status" control offering only the transitions legal from the current state (§12.7) — an illegal transition is not merely rejected, it is not offered. Each change requires a confirmation and accepts an optional note.
ItemsThumbnail, name (linking to the product), attributes, SKU, unit price, quantity, line total. Items whose product has since been deleted render from their snapshot with a muted "no longer in catalogue" marker.
PaymentMethod, the number the customer said they would pay from, expected total, amount received. Recorded payments listed with status, provider reference, amount, verifier and timestamp. A "Verify payment" action opens the dialog from §12.8; a "Record manual payment" action covers cash. "Issue refund" is present when the order is paid, behind the payment.refund permission.
FulfilmentShipping method and cost, delivery address with a copy-all control, a tracking reference field, "Print packing slip", "Print invoice", and "Mark shipped" / "Mark delivered".
TimelineThe full order_events stream, newest first: actor, action, before and after, timestamp, and any note. Notifications sent appear here too, so "did we tell the customer?" is answerable.
CustomerName, email, phone, and whether the account is registered or guest. For registered customers: total lifetime orders and value, and a link to their record. A "Contact" control offers WhatsApp, call and email with the order number prefilled.
Internal notesThreaded, timestamped, attributed. Staff only, never exposed on any customer-facing endpoint.
ActionsResend confirmation · Regenerate payment link · Cancel order (with reason) · Duplicate as a new order · Create invoice from this order.
