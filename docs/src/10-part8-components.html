Part EightComponent Catalogue

Every component the platform needs, with its responsibility and its public contract. Components live in packages/ui when they are design-system primitives with no domain knowledge, and in apps/web/src/components when they know about products, orders or carts. That boundary is enforced by lint rule: nothing in packages/ui may import from apps/web.

8.4 Admin components

8.4.1 DataTable

The workhorse of the admin console. One component serves products, orders, invoices, customers, categories, subcategories, shipping methods, banners, campaigns, contacts, searches, comments, reviews, staff and the audit log.

interface DataTableProps<T> {
  columns: Column<T>[]          // key, header, render?, sortable?, width?, hideBelow?
  rows: T[]
  rowKey: (row: T) => string

  loading?: boolean             // renders skeleton rows at final height
  error?: Error                 // renders an inline retry panel
  emptyState: EmptyStateProps

  // selection
  selectable?: boolean
  selectedKeys?: string[]
  onSelectionChange?: (keys: string[]) => void
  bulkActions?: BulkAction[]    // label, icon, tone, requiresConfirm, onRun

  // server-driven state — the table never fetches, it only reports
  sort?: { key: string; dir: 'asc' | 'desc' }
  onSortChange?: (s: Sort) => void
  page: number
  pageSize: number
  total: number
  onPageChange: (p: number) => void
  onPageSizeChange?: (n: number) => void

  search?: { value: string; placeholder: string; onChange: (v: string) => void }
  filters?: FilterDescriptor[]
  rowActions?: (row: T) => RowAction[]
  onRowClick?: (row: T) => void
  density?: 'comfortable' | 'compact'
}

Behaviour that is uniform everywhere it is used: sticky header on scroll; sortable headers with an aria-sort attribute; a select-all checkbox that selects the current page only, with a "Select all n matching" affordance when more exist; a bulk-action bar that slides in above the table when anything is selected, showing the count and a "Clear" control; search debounced at 300 ms and written to the query string; row actions in a trailing column, collapsing to an overflow menu below lg; and horizontal scroll confined to the table's own container so the page never scrolls sideways.

8.5 Contracts every component honours

  • Controlled by default. Components take value and onChange. Uncontrolled variants exist only where React Hook Form needs an uncontrolled input for performance.
  • No data fetching in presentation components. Fetching lives in route loaders and hooks. A component that fetches cannot be reused with different data and cannot be tested without a network mock.
  • Every interactive element has an accessible name. Enforced by eslint-plugin-jsx-a11y and by an axe pass in the component test suite.
  • Loading, empty and error are props, not afterthoughts. Any component that renders a collection must accept all three; the type system requires emptyState.
  • No hard-coded colour, spacing or font values. Only tokens. Enforced by a stylelint rule.
  • No hard-coded user-facing strings. All copy is resolved through the i18n layer (§19.8), even while only English ships.
  • Each component ships with a Storybook story per state. The story set is the visual regression suite (§21.1).
