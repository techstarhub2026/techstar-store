Appendix FSeed Data Plan

Order matters: SKU allocation reads the parent record, so a child can never be seeded before its parent. The seed is idempotent — running it twice produces the same database, never duplicates — which is what makes it safe to re-run against a developer's existing schema.

StepDataContents and notes
1PermissionsAll ~60 permission keys from §11.5, grouped. Idempotent upsert on key.

3Owner accountOne staff user from SEED_OWNER_EMAIL and SEED_OWNER_PASSWORD. In production the password must be changed at first sign-in; the seed refuses to run with a default password when NODE_ENV=production.

Appendix HAlternative Stack: PHP / Laravel

Decision D1 selected Node.js. If PHP is preferred — and the workstation's existing XAMPP install is a fair reason to prefer it — nothing in Parts 5 to 18 changes. The data model, API contract, business rules, UI specification and admin design are all runtime-neutral. Only the server implementation is affected.
