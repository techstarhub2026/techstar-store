4.2.1 Why the API is same-origin

The API is mounted at /api on the same origin as the SPA, exactly as the reference platform does. This is not cosmetic: it lets the refresh token live in a SameSite=Strict httpOnly cookie without a cross-site cookie exemption, removes CORS preflight latency from every mutation, and keeps one TLS certificate. Development uses a Vite proxy so the same-origin assumption holds locally.

4.3 Request lifecycle

Every API request passes through the same ordered pipeline. The order matters and is normative.

#StageResponsibility
1requestIdAssign a ULID, attach to the async-local context, echo as X-Request-Id. Every log line and error response carries it.
2helmetSecurity headers including a strict Content-Security-Policy (§11.8).
3corsSame-origin by default; an explicit allowlist only when an alternate front end is deployed.
4Body parsingJSON limited to 256 KB; multipart handled by multer only on upload routes, with per-file and per-request caps (§11.7).
5Rate limitingRedis-backed sliding window. Tiers in §10.9.
6AuthenticationVerify the access token if present; populate req.auth = {userId, role, permissions}. Never rejects here — absence of a token is a valid state for public routes.
7Route matchExpress router.
8AuthorisationRoute-declared guard: requireAuth(), requireRole(), requirePermission(). Rejects with 401 or 403.
9ValidationZod parse of params, query and body. On failure emits the 422 shape in §10.2. The parsed, typed value replaces the raw input — controllers never see unvalidated data.
10ControllerTranslates HTTP to a service call and back. Contains no business logic.
11ServiceDomain logic, invariants, transaction boundaries. The only layer allowed to enforce a business rule.
12RepositoryPrisma access. No domain logic, no HTTP concepts.
13SerialisationExplicit response DTO. Never returns an ORM entity directly — this is what stops password hashes and internal flags leaking.
14AuditSuccessful mutations by staff append an audit record (§14.18) on the same transaction.
15Error handlerMaps typed domain errors to status codes (§20.4); logs with request id; never leaks stack traces in production.

4.4 Environments

EnvironmentPurposeConfiguration
localDeveloper workstationDocker Compose brings up MySQL, Redis and MailHog. Media on local disk. SMS adapter is a console stub. Payments in sandbox. Seed data from Appendix F.
testAutomated suitesEphemeral MySQL schema per run, migrated then truncated between tests. All outbound adapters are fakes. No network egress permitted.
stagingPre-production verificationProduction topology at smaller size. Anonymised copy of production data. Real SMS and email to an allowlist only. Payment aggregator in sandbox. noindex enforced at Nginx.
productionLiveFull topology per §22.1. Debug endpoints absent from the build, not merely disabled.
Configuration rule Configuration is read from the environment exactly once, at boot, through a Zod schema that fails fast on a missing or malformed variable (§20.8). No process.env access anywhere else in the codebase. This is what prevents the reference platform's failure mode of shipping a development hostname to production (R10).

4.5 Repository layout

A single repository with npm workspaces. One git clone, one npm install, one command to run everything.

techstar-store/ ├── apps/ │ ├── web/ React SPA — storefront and admin console │ │ ├── public/ │ │ ├── src/ │ │ └── vite.config.ts │ └── api/ Express API + Socket.IO gateway + workers │ ├── prisma/ │ │ ├── schema.prisma │ │ ├── migrations/ │ │ └── seed.ts │ └── src/ ├── packages/ │ ├── contracts/ Zod schemas + inferred TS types shared by web and api │ ├── ui/ Design-system components and SCSS tokens │ └── config/ Shared eslint, tsconfig, prettier ├── docker/ │ ├── docker-compose.yml │ └── nginx/ ├── docs/ This specification and derived artefacts ├── scripts/ Migration, backup, seed and ops helpers └── package.json Workspace root
Why packages/contracts is the keystone Every request and response shape in Part 10 is defined once as a Zod schema in this package. The API validates against it; the React forms validate against it; TypeScript types are inferred from it on both sides. A field added to a form without a corresponding schema change fails to compile. This single package is what makes a specification this large stay true to the code six months after it is written.
